# 🚀 AutoISO - 分布式高可用自动封装与转存系统

![Version](https://img.shields.io/badge/version-v1.7.9-blue.svg)
![Python](https://img.shields.io/badge/python-3.8%2B-blue)
![License](https://img.shields.io/badge/license-MIT-green)

AutoISO 是一个专为 PT (Private Tracker) 玩家和影视发烧友设计的**分布式自动化存储工作流系统**。它能够完美联动 qBittorrent、TMDB 以及 CloudDrive2，实现从“下载完成”到“生成 ISO 镜像 / 智能重命名 / 剧集逐集转存”，再到“跨国无缝转存至云盘”的全自动、无人值守体验。

## ✨ 核心特性

- 🕸️ **分布式架构 (Master-Edge)**：以群晖 NAS 作为中央主控，支持挂载无数个海外 VPS 作为“边缘节点”。统一在 NAS 面板下发指令、查看进度、全局管理。
- 📦 **自动化 ISO 封装**：智能识别任务目录类型——原盘结构（含 `BDMV` / `VIDEO_TS`）自动调用 `genisoimage` 底层无损封装，单文件极速直拷，纯非媒体目录兜底打 ISO。
- �️ **剧集组智能处理**：自动识别多集媒体文件夹，逐集协同打标、逐集转存上传。Web UI 以集数徽章（如 `3/24`）直观展示单集进度，支持断点续传，中途中断可无损续跑。
- 🏷️ **精细化标签插入引擎**：“旁路改名”与“极速贴标”双轨机制。**自定义标签与大小标签各自独立配置**插入模式（智能 / 年份后 / 扩展名前 / 锚点前 / 锚点后）、锚点词组与过滤词（多词以 `|` 分隔）。完美兼容 MoviePilot 等外部媒体库的硬链接整理流程，支持免封装跨目录秒切。
- 📏 **文件大小后缀**：可按 `[{value}{unit}]` 模板自动为文件注入体量标签，随自定义标签一同下发至边缘节点。
- 🔀 **三档上传策略**：每个节点可独立选择跟随全局定时、立即强传、或使用独立 Cron 表达式，灵活适配不同线路与成本策略。
- 🎬 **TMDB 智能刮削引擎**：内置自动化名称清洗与 TMDB 匹配算法，为枯燥的文件赋予精美的海报与影视元数据，支持多标签多彩高亮展示，Web 端一键手动纠错与重新绑定。
- ☁️ **无缝对接 CloudDrive2**：针对 CD2 (FUSE) 挂载盘特性深度优化，彻底打通本地与云端的物理壁垒，支持跨国大文件稳定推送。
- 🛡️ **工业级防假死与自愈机制**：VPS 边缘节点采用“双线程高频心跳 + 断网自毁重生”架构，彻底告别 TCP 状态僵死与网络波动导致的节点失联。
- 📱 **Telegram 实时推送**：任务封装、上传、失败全流程精准推送，可逐项开关通知类型，随时随地掌握系统动态。

## 🚀 部署与安装

### 1. 中央主控部署 (推荐使用 Docker)

为了保证环境的一致性与最佳体验，强烈推荐使用 Docker Compose 进行一键部署。

**方案一：Docker Compose部署**
在你的 NAS 或服务器上新建一个目录（例如 `autoiso`），并在下面建个 `data` 空文件夹和一个 `docker-compose.yml` 文件，填入以下内容：

```yaml
version: '3.8'

services:
  autoiso:
    # 如果你本地有源码想自己编译，请使用 build: .
    # 此处默认使用云端预编译的最新镜像
    image: xeiderx/autoiso:latest 
    container_name: autoiso
    restart: unless-stopped
    ports:
      - "5123:5000"
    environment:
      # 时区，影响 Cron 定时与日志时间
      - TZ=Asia/Shanghai
      # SQLite 数据库位置（与下方 ./data:/data 对应，请勿随意修改右边路径）
      - DB_PATH=/data/autoiso.db
      # 封装产物的输出目录（与下方 /output 挂载点对应）
      - OUTPUT_DIR=/output
    volumes:
      # 映射数据库与系统配置 (必填)
      - ./data:/data
      
      # 【请修改】映射 qB 下载完成的路径 (可以映射整个文件夹)
      # ⚠️ 注意：冒号右边的路径，必须和你 qBittorrent 容器内的路径完全一致！
      - /path/to/your/downloads:/Downloads
      
      # 【请修改】映射 ISO 封装输出的临时存放点
      - /path/to/your/output:/output
      
      # 【请修改】映射 CD2 网盘的底层挂载路径 (rslave 参数必填)
      - /path/to/your/CloudNAS:/CloudNAS:rslave
```

> **提示**：除上述三项外，绝大多数功能参数（上传定时、监控标签、重命名规则、Telegram、TMDB 等）均可在部署后于 Web UI「系统设置」中直接完成，无需改动 Compose 文件。

**方案二：源码直接运行 (适合开发者)**
如果你希望直接在宿主机运行，请确保已安装 Python 3.8+ 以及 `genisoimage`。
```bash
# 克隆仓库
git clone https://github.com/xeiderx/AutoISO.git
cd AutoISO

# 安装依赖
pip install -r requirements.txt

# 运行主控服务
python3 app.py
```

> **注**：默认运行在 `0.0.0.0:5000`。首次访问将自动初始化默认管理员账号（账号：`admin`，密码：`admin123`），请登录后立即前往“系统设置 → 安全设置”修改密码。

### 2. (可选)边缘节点部署 (VPS 一键安装)

**完全无需手动配环境！**
1. 登录 AutoISO 主控 Web UI。
2. 进入左侧【边缘节点】菜单，点击 `添加节点` 并填写 VPS 本地 qB 信息及 CD2 挂载路径。
3. 保存后，点击表格右侧的绿色 **[部署]** 按钮。
4. 复制弹出的 Bash 部署代码，直接粘贴到你的 VPS SSH 终端执行即可。

> *部署脚本会自动安装运行环境、拉起 CloudDrive2 容器、建立双线程身份凭证，并将其注册为 `systemd` 守护进程（`Restart=always`、`RestartSec=10`），实现开机自启与断网故障自愈。*

**节点日常运维**：节点列表右侧同样提供两个辅助按钮：

- **[卸载]**：生成终极清理脚本，会一并停用并移除 `autoiso-agent` 服务、节点代码目录，并停删 CloudDrive2 容器。
  > ⚠️ **注意**：该脚本会执行 `rm -rf /CloudNAS`，即删除 CD2 的整个挂载根目录及其中的配置数据。请确认该目录仅用于 CD2 挂载、且无其他数据后再执行。
- **[日志]**：一键复制日志查看命令，粘贴到 VPS 终端即可实时观察节点工作详情：

```bash
journalctl -u autoiso-agent -f
```

> **提示**：VPS 节点会在每轮任务开始时向主控实时拉取最新配置，因此**修改重命名规则、过滤词等配置后无需重启节点服务即可生效**；但若节点上运行的是旧版部署脚本，则需重新执行一次 [部署] 覆盖更新。

## ⚙️ 核心使用流程

### 1. 三条自动化流水线

**① 标准封装流**
在任意节点为下载完成的种子打上 `待封装` 标签。系统将自动提取用户设定的自定义后缀（如 `[特效字幕]`）与大小后缀并智能插入文件名中，随后按目录类型分流处理，完成后自动变更为 `已封装` 标签：

- **原盘结构**（含 `BDMV` / `VIDEO_TS`）→ 调用 `genisoimage` 封装为 `.iso` 镜像；
- **单文件** → 极速直拷，跳过镜像生成；
- **纯非媒体目录**（仅含 nfo / 图片 / Sample 等）→ 兜底封装为 ISO。

**② 旁路改名流（完美搭档 MoviePilot）**
当种子被打上监控的整理标签（默认 `MOVIEPILOT, 已整理`），主控将跳过 ISO 封装，直接把硬链接缓存区的文件精准打上你的自定义后缀，并瞬间转移至最终媒体库目录，同时追加 `已重命名` 防重标签，全程无缝触发 TMDB 刮削展示大厅。若开启“缓存区全量转移”，则无差别物理转移缓存区内的所有文件，不再依赖触发标签命中。

**③ 剧集流（多集媒体文件夹）**
当任务目录被判定为多集媒体文件夹（非原盘结构）时，系统自动进入剧集组流程：

1. **逐集协同打标**：为每一集单独插入自定义标签与大小标签，命名结果确定性可复现；
2. **生成清单**：在输出目录写入 `.autoiso_manifest.json`，记录全部集数与相对路径，作为进度跟踪与断点续传依据；
3. **逐集上传**：按清单顺序将单集逐个移入 CloudDrive2 挂载点，Web UI 实时显示 `已上传/总集数`；
4. **同名兜底**：跨季存在同名裸文件（如 `S01/ep01.mkv` 与 `S02/ep01.mkv`）时，后续文件自动补 `S02-` 季前缀，杜绝互覆盖。

> *剧集单集以**扁平散文件**形式落在网盘接收根目录，不再放入 `组名/` 子目录，以避免云端归档工具中途移走父目录导致其余集上传失败。*

### 2. 上传放行与策略

主控通过“通行证”机制统一控制边缘节点何时开始转存，共三档策略：

- **跟随全局**：按系统设置的 Cron 表达式（如 `0 2 * * *` 凌晨 2 点）批量放行全部节点。
- **立即强传**：节点收到任务后跳过定时规则，封完即走，适合小盘应急。
- **独立定时**：为单个节点单独指定 Cron 表达式，与全局节奏解耦。

> **放行窗口说明**：定时策略并非“到点瞬间一刀切”，而是判断当前时间是否落在 Cron 触发点之后的 **5 分钟窗口**内。节点按轮询节奏取通行证，因此封完到实际放行之间存在数分钟的延迟属于正常现象。

此外，在“待上传队列”中可对任意任务点击 **立即上传** 单独放行；已上传过的任务会显示为 **重新上传**，便于补传或覆盖。任务因断网中断后，重新触发时会自动跳过已完整复制的内容，实现断点续传。

主控 NAS 端的大文件上传在仪表盘“上传动态”面板中提供实时控制：可 **暂停 / 继续 / 中止** 当前传输，进度、速度与剩余时间同步刷新。

### 3. 差异化空间清理

- **NAS 主控端**：由于本地空间通常较充裕，您可以在“系统设置 → 全局上传”中自由开关**“上传后删除已封装文件”**选项，灵活决定是否保留本地备份。
- **VPS 边缘节点**：受限于云服务器的高昂存储成本，VPS 在完成向网盘的转移后，会**强制自动清理**本地的临时缓存（含 ISO 映射表），严防小盘爆满。

## ⚠️ 最佳实践与注意事项

**💡 强烈建议一：为 VPS 节点分配专属的“空目录”作为网盘接收站**

在使用海外 VPS 节点配置 CD2 的底层挂载路径（`cd2_path`）时，**千万不要**将其直接挂载到包含海量老文件的庞大影视库目录中。强烈建议在网盘中新建一个专门的空文件夹（例如：`/VPS_Transfer`），专门作为中转接收站。

* **原理解析（核心避坑）**：由于大多数 VPS 使用的是海外 IP，而有些网盘对海外 IP 的 API 请求有着极其严格的**风控机制**。如果挂载的目录中包含海量文件，CloudDrive2 在底层同步时会频繁调用网盘的接口去扫描和比对目录树。**这种高频的 API 交互叠加海外 IP，极易触发这类网盘的风控雷达**，直接导致 VPS 网络假死、上传中断甚至账号限制。而使用**专属的空目录**，能将 API 调用量降到绝对的最低值，让 VPS 像个“透明人”一样只负责底层的数据传输，完美规避网盘风控！

**💡 强烈建议二：剧集请统一上传至扁平目录，不要人为建季文件夹**

剧集单集采用扁平化上传是刻意设计。若放入 `剧名/Season 01/` 这类子目录，云端归档工具（如 symedia）可能在收录后把整个父目录移走，导致尚未上传完成的其余集数在原路径上“找不到目标目录”而报错中断。保持散文件落盘可让每集互不干扰、独立完成。

**💡 强烈建议三：善用“过滤词”精准控制标签落点**

当锚点词组（如 `UHD`）在文件名中出现多次、而你只想在特定位置插入标签时，可把不应命中的上下文（如 `WEB-DL`、`DTS-HD`）填入**过滤词**。系统会按“出现位置”逐个判断：落进过滤词区间的锚点位置将被跳过。该配置对自定义标签与大小标签分别独立生效。

## 🛠️ 常见问题 (FAQ)

**Q: 为什么在 VPS 上点击“立即上传”后，网盘里没有立刻出现文件？**
A: 这是正常的物理机制。VPS 收到立即上传指令后，脚本会瞬间将数十 GB 的文件移入 CloudDrive2 的本地 FUSE 缓存中（UI 会立刻变绿显示“已上传”）。随后，CD2 会在后台吃满你的 VPS 带宽，将文件通过跨国网络推向国内网盘。这个过程受限于实际网速，可能需要十几分钟至数小时。此时网盘端暂不显示文件，请耐心等待，不必焦虑。

**Q: 为什么重启主控 NAS 的 Docker 容器后，VPS 会在短时间内断联？**
A: 容器重启会重置宿主机的 TCP NAT 状态表，导致 VPS 原本的长连接（Keep-Alive）发送的数据包被默默丢弃（TCP 假死）。**不必担心**，本系统为 VPS 节点设计了“连续通信失败触发系统级自尽”功能：当异常计数累积到阈值（约 60 秒）时进程主动退出，Linux 的 `systemd` 会在 10 秒内将其满血复活，重新发起全新的握手连接，实现对假死状态的无感自愈。

**Q: 为什么我的剧集在网盘里是一堆散文件，而不是整季文件夹？**
A: 这是有意为之的扁平化策略，原因见上方「最佳实践二」。若你把单集手动归入季文件夹，反而可能破坏未完成集数的上传路径。

**Q: 为什么标签被插到了意想不到的位置？**
A: 请检查「命名与标签」页面的插入配置。自定义标签与大小标签拥有**各自独立**的插入模式与锚点词组，二者互不干扰。常见的三种情形：
- 选用了 `指定词组之前/之后` 但**未填写锚点词组** → 回退为兜底插入位置；
- 锚点词组在文件名中多次出现且**未配置过滤词** → 命中了非预期的那个位置；
- 两个标签最终算出的插入点相同 → 由“相对顺序”配置决定谁在前。

**Q: 我改了过滤词 / 重命名规则，为什么 VPS 上没生效？**
A: 节点每轮任务开始时会自动向主控拉取最新配置，正常情况下无需重启服务。但如果你的 VPS 上运行的是**较早版本**的部署脚本（可能不支持过滤词等新参数），则需要回到「边缘节点」页面重新点击 **[部署]**，用最新脚本覆盖更新一次。

**Q: 为什么我的刮削记录里没有中文名，而是一串英文？**
A: AutoISO 拥有智能的名称清洗机制，但遇到命名极其不规范的资源时仍可能刮削失败。你只需进入“刮削记录”页面，找到那张失败的灰色卡片，点击“手动匹配”，输入中文名或 TMDB ID 即可一键绑定。

**Q: 如何查看 VPS 节点的真实后台干活进度？**
A: 登录对应 VPS 的 SSH 终端，执行 `journalctl -u autoiso-agent -f`，即可实时查看极其详尽的双线程运作、打包进度与跨国传输日志。（也可在「边缘节点」页面点击 **[日志]** 按钮一键复制该命令。）
